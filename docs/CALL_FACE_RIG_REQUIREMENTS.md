# 오또 말하기 모델: 필요한 작업과 검수 기준

## 현재 확인 결과
- 원본 oddo_rigged.glb에는 jaw/lip/mouth 제어 뼈가 없다.
- 기존 tankachu_animated.glb의 얼굴 모프는 Blink, Happy 두 개다.
- 검은 원형 메시를 입 앞에 겹쳐 키우는 시도는 사용자 거절로 제거했다. 재사용하지 않는다.
- 2026-11-08: 원본 입 경계를 분리한 사본에 AA/E/O/U 모프와 안쪽 공간을 추가하고 통화 위젯에 연결했다. 한글 글자에서 추정한 입 모양을 TTS 시작·진행·완료 이벤트 및 서버 재생 길이에 맞춘다. 음성 파형 기반 정밀 정렬은 아직 아니다.

## 2026-11-08 연결 구조와 남은 검수
- `prototype_face_seam.py` → 검토 모델 생성 후 `build_call_motion.py --face` → `assets/models/oddo_call_face.glb`로 재생성한다. 기존 원본 모델과 입 없는 통화 모델은 보존한다.
- `CallLipTrack`이 한글 모음과 양순음 닫힘·쉼표를 AA/E/O/U 타임라인으로 변환한다. `CallMascot3d`는 새 발화에서 타임라인을 보내고 기기 TTS의 글자 진행 이벤트로 위치를 보정한다. 서버 음성은 재생 길이에서 속도를 계산한다. 완료·취소 시 즉시 입을 닫으며 끝난 음절을 반복하지 않는다.
- `call_face_driver.dart`는 본체·입 안쪽의 실제 모프를 동시에 제어하고 깜빡임을 유지한다. 몸 동작 클립은 얼굴 가중치를 덮어쓰지 않는다. 화면 비활성·동작 줄이기·위젯 종료 시 얼굴 갱신을 중단한다.
- model_viewer_plus 1.10.0의 번들 JS에는 공개 모프 제어 API가 없어 내부 scene 어댑터를 사용한다. 패키지/번들 변경 시 반드시 재검증한다. 구조를 찾지 못하면 입 제어를 건너뛰어 닫힌 모델을 유지한다. 새로운 패키지는 추가하지 않았다.
- 글자별 시간 추정이 실제 발음의 장단·연음·쉼과 완벽히 맞지는 않는다. 브라우저 검토에서는 한국어 음성이 없어 무음 대사 구동만 확인했다. 실제 폰의 소리·입 일치와 장시간 성능은 별도 확인이 필요하다.

## 제대로 된 말하기 모델의 최소 조건
1. 기존 입술 경계를 따라 위·아래 입술이 실제로 분리되어 열릴 것.
2. 입 안쪽 공간과 턱·입술 변형이 이어져 겹친 스티커처럼 보이지 않을 것.
3. 닫힘(ㅁ·ㅂ·ㅍ), 벌림(ㅏ·ㅓ), 좌우 넓힘(ㅣ·ㅔ), 오므림(ㅗ·ㅜ)의 독립 형태를 갖출 것.
4. 모델의 중립 자세, 털·얼굴·체형·기존 눈 표정이 유지될 것.
5. GLB로 내보낸 후 실제 렌더에서도 모프가 보존되고, 각 모양을 0~1로 부드럽게 섞을 수 있을 것.
6. 입 모양은 단순 반복 주기가 아니라 음성/발음 시각에 맞춰 구동할 것. 실제 발화 시작·끝, 무음 구간에 닫힘을 지킬 것.

## 모델 작업 후 앱 연결 범위
- 음성 구간과 발음별 입 모양의 타임라인을 생성한다.
- 실시간 모프 제어가 가능한 렌더러로 연결하고, 녹음 중 상대 발화와 사용자 발화를 구분한다.
- 베이스라인은 기존 6문장 읽기를 유지하며 사용자 발화 중 오또 음성을 재생하지 않는다.
- 정면·45도·입 최대 열림·모음 전환·실제 한국어 문장으로 먼저 검수한 뒤 기기에 반영한다.

## Tripo 조사 범위
공식 문서에서 확인한 것은 스켈레톤 자동 리깅과 동작 프리셋이다.
정교한 얼굴/발음별 리깅이 자동 완성된다는 보장은 확인하지 못했다.
일반 자동 리깅 또는 'talking' 몸짓만으로 이 요구를 충족했다고 판단하지 않는다.

## 일정 판단
현재 작업을 고품질 립싱크 완료로 표시하지 않는다.
실험용 얼굴 변형과 앱의 글자 기반 동기화는 연결했지만, 실제 음성과 외관 검수 및 성능 확인이 남아 있다.
'고정 안내문을 미리 제작한 영상으로 재생'은 발표용 대안이 될 수 있지만, 자유 대화용 3D 립싱크와는 다르다.
